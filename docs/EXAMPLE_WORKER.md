# 예문 생성 워커 — Windows 스케줄러용 사양

> 목적: 서버 연동(개인 Firebase) 사용자의 단어장에서 **예문(ex)이 비어 있는 단어**를 찾아 LLM으로 예문을 생성해 채워 넣는다. 앱은 다음 동기화 때 예문을 자동으로 받는다.
> 실행 주체: **Windows PC의 파이프라인 스케줄**(기존 idea-pipeline 일일 실행에 한 단계 추가 또는 별도 작업). 이 문서는 구현·운영 방법 기술이 목적이며, 워커 코드는 Windows 쪽에서 작성한다.
> ⚠️ 이 리포는 public — **DB 주소·API 키를 이 리포에 절대 커밋하지 않는다.** 주소는 Windows 로컬 설정(예: `harness\telegram\state\` 옆 비공개 설정 파일)에만 둔다.

## 1. 동기화 프로토콜 (앱과 동일해야 함 — index.html 9960~9977 기준)

- **저장소**: Firebase Realtime Database REST. 주소는 `https://<프로젝트>.firebaseio.com/<경로>.json?auth=<시크릿>` 형태 (앱 설정 화면이 만들어주는 그 URL 그대로).
- **읽기**: `GET <url>` → 전체 상태 JSON 1개:
  ```json
  { "version": 1, "words": [ ... ], "log": { ... }, "settings": { ... }, "updated": 1757600000000 }
  ```
- **쓰기**: `PUT <url>` (Content-Type: application/json) — **전체 상태를 통째로** 다시 쓴다 (부분 PATCH를 앱이 쓰지 않으므로 워커도 동일 방식 유지).
- **단어 스키마**: `{ id, hz(한자), py(병음 canon), mean(뜻), ex(예문), added, stage, due, reps, lapses, last }` — 워커는 **ex 외 어떤 필드도 수정 금지** (학습 진행 데이터 훼손 방지).
- **메아리 감지**: 앱은 `updated` 값이 자기가 쓴 값과 같으면 무시한다. 워커가 쓸 때는 반드시 `updated: <현재 epoch ms>`로 갱신해야 앱이 새 데이터로 인식한다.

## 2. 워커 절차 (한 사이클)

1. `GET` 전체 상태 → `words` 중 `!w.ex || !w.ex.trim()`인 단어 목록 추출. 없으면 종료.
2. 각 단어에 대해 LLM으로 예문 생성 (아래 §3 규격).
3. **경합 최소화**: 쓰기 직전 `GET`을 한 번 더 해서 최신 상태를 다시 받고, 그 위에 ex만 병합(단어 id 기준) 후 `updated` 갱신 → `PUT`. (전체 PUT 방식이라, 사용자가 앱을 쓰는 중이면 마지막 쓰기가 이긴다 — **심야 실행 권장**, 1~2단계와 3단계 사이 간격 최소화.)
4. 처리 결과(생성 N건, 스킵 사유)를 파이프라인 실행 보고에 남긴다.

## 3. 예문 생성 규격

- 문장: **단어를 포함한 중국어 간체 1문장** (HSK 1~3 수준 어휘 위주, 8~14자), + 병음(성조 부호), + 한국어 번역.
- `ex` 필드 저장 형식(한 줄): `中文例句 (pīnyīn) — 한국어 번역`
  - 예: `我们明天一起去图书馆。(wǒmen míngtiān yìqǐ qù túshūguǎn.) — 우리 내일 같이 도서관에 가.`
- 이유: 앱은 ex를 단일 텍스트로 표시하므로(목록·복습 정답 카드) 구조 없이 읽혀야 하고, 예문 복습 카드(빈칸 채우기)가 `한자 문장에서 해당 단어 위치`를 찾을 수 있게 **대상 단어가 문장에 원형 그대로 포함**돼야 한다.
- 검증(생성 후 필수): ①문장에 `hz`가 부분 문자열로 포함 ②괄호 병음이 문장 글자 수와 대체로 정합 ③금칙: 뜻 필드를 그대로 번역문에 복붙하지 않기.

## 4. Windows 스케줄 등록 (제안)

- 기존 매일 process 실행 후단에 추가하거나, 별도 작업으로: `python worker/example_worker.py` (워커 스크립트는 Windows 쪽 harness 리포 또는 로컬에 두고, 이 리포에는 두지 않는다 — public이기 때문).
- 설정 파일(비공개, 예: `example_worker.config.json`): `{ "sync_url": "...", "batch_max": 20, "model": "..." }`
- 안전핀: 한 사이클 최대 20단어(폭주 방지), PUT 실패 시 재시도 1회 후 보고만, **words 배열 길이가 GET 시점보다 줄어드는 PUT은 중단**(데이터 손실 방어 — 병합 버그 감지).

## 5. 앱 쪽 대응 (이 리포에서 구현)

- 설정에 저장 방식 토글: **로컬 전용 / 단어장 서버 연동**(개인 서버 보유자용). 연동 모드에서만 서버 주소 입력란 노출.
- 연동 모드일 때 안내 표시: "서버에 연결하면 예문이 자동으로 채워질 수 있어요 — 컴퓨터에서 예문 생성기를 돌리는 방법은 docs/EXAMPLE_WORKER.md 참조" (생성기는 별도 실행이 필요함을 명시 — 자동으로 되는 것처럼 과장하지 않기).
- 예문 복습 카드(빈칸 채우기)는 ex 존재 단어에만 출현 — 로컬/서버 모드 무관하게 동일 동작. 로컬 전용 사용자는 내보내기(TSV)→예문 생성→가져오기 경로 사용 가능.
